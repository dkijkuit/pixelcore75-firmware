# AGENTS.md

Firmware for the PixelCore75 ESP32-S3 LED matrix panel (Huidu WF2-compatible hardware). Despite the parent folder being named `java/`, this is a C++ PlatformIO project — no Java, no Maven/Gradle.

## Commands

PlatformIO is installed via the VSCode extension; `pio` is NOT on PATH. Use the full path:

```sh
~/.platformio/penv/bin/pio run                         # build (debug env, default)
~/.platformio/penv/bin/pio run -e pixelcore75_release  # build release
~/.platformio/penv/bin/pio run -t upload               # flash to connected board
~/.platformio/penv/bin/pio device monitor              # serial monitor (115200, from platformio.ini)
```

No tests, lint, or formatter are configured. `pio run` is the only verification step.

## Structure

- `src/main.cpp` — entire firmware (setup/loop, WiFi, MQTT, BLE provisioning, display)
- `include/images.h` — bitmap assets; `include/image_utils.h` — draw helpers + `ScreenImage` enum
- `platformio.ini` — two envs: `pixelcore75_debug` (default) and `pixelcore75_release`
- `lib/` and `test/` are empty PlatformIO boilerplate; don't add anything there by accident

## Gotchas

- Board config lives in `platformio.ini`; pin mappings are `#define`s at the top of `src/main.cpp` (board = wifiduino32s3, 8MB flash, custom `partitions_pixelcore75.csv` — app 3MB + LittleFS ~4.9MB + coredump, using the full chip; the stock `huge_app.csv` only addressed the first 4MB — USB CDC on boot — serial goes over native USB, not UART).
- The panel is driven on the X2 port pins; the X2 E-pin is unknown (`-1`), so 1/32-scan panels don't work on X2.
- Runtime config (WiFi SSID/password, MQTT server/port, brightness) persists in NVS via `Preferences` (namespace `cryptoticker`) and is provisioned over BLE GATT when no WiFi credentials are stored, or when the test button (GPIO 17) is held at boot.
- MQTT (base topic = client ID `PXCORE75-<MAC>`): base-topic payloads must be exactly 4096 bytes (64×32 RGB565, little-endian) — anything else on the base topic (including the server's zero-length retained-clear while an animation is displaying) is silently ignored, and a static frame stops any playing animation (but keeps the slot cache files). On boot/connect the retained base frame (if any) is drawn; if none was retained the last played slot animation auto-resumes — the server clears the retained frame during animation slots for exactly that reason.
- Animations: send 14 bytes to `<base>/anim/start` — `"ANIM"` magic (u32 LE) + frameCount (u16, 2–200) + delayMs (u16, ≥10) + uploadId (u32 LE) + flags (u8) + slot (u8, 0–31). flags bit0 = stage-only; bits 1–2 = codec: 0 = RAW (v1), 1 = PAL_RLE (v2), 2–3 = unsupported (the whole ANIM is silently ignored; the server times out and re-sends as RAW). Then frameCount messages to `<base>/anim/frame` — `"ANIF"` magic (u32 LE) + frameIdx (u16, must be sequential from 0) + payload whose shape depends on the codec: codec 0 sends exactly 4102 B per frame (4096-byte raw RGB565 LE frame, wrong length silently dropped); codec 1 sends v2 frames of 103–4103 B = frameFlags (u8) + body — frameFlags 0 = RAW body (4096 B, total 4103), frameFlags 1 = PAL_RLE body = 16-entry RGB565 LE palette (32 B) + `(run u8, colorIdx u8)` pairs covering all 2048 pixels, where runs never cross row boundaries (64 px per row, each row's runs sum to exactly 64; run 1–64, colorIdx 0–15; minimum 1 run/row gives the 103 B floor). v2 frames are structurally validated at ingest (length range, frameFlags ≤ 1, pair parity, per-row run sums, run/colorIdx bounds, 2048 total pixels) and any violation aborts the whole upload (`abortAnimUpload`) so garbage never reaches flash. Uploads stage into `/anim_up.bin` (the file handle stays open for the whole upload — per-frame open/close plus LittleFS alloc/erase stalls starve the animation loop; a new anim/start aborts an in-flight upload cleanly) and land in the persistent slot file `/a<slot>.bin` on the last frame. Without stage-only, the last frame also plays the slot immediately; with stage-only the panel waits for a 9-byte `"ANIP"` + slot + uploadId message on `<base>/anim/play` (a play arriving mid-upload is remembered and applied on completion). ANIP doubles as the content-hash fast path: with a non-zero uploadId the panel plays (and publishes `ANIL`) only when the slot's persisted uploadId matches — on mismatch, or when the slot file is missing/corrupt, it stays silent (no play, no `ANIL`) and the server's existing 2 s play-ack timeout falls back to an inline upload; uploadId 0 keeps the legacy unconditional play (old-server compat). The persisted ids live in `/slotidx.bin`: magic `"SLTI"` (u32 LE) + version u8 (=1) + 32 × u32 uploadId LE (entry index = slot, 0 = unknown), rewritten whole (133 B) whenever an entry changes — set when the staging file is renamed onto the slot on upload completion, zeroed for every slot file the upload space ladder deletes and for corrupt files deleted on read failure. Boot loads it only if magic/version/size are valid, else all zeros (never reformats); a reflash or wiped index just costs one redundant upload, since the server re-uploads on silence. Static frames and reboots keep slot files; a corrupt file is deleted on read failure. Space ladder on upload (worst-case estimate `4 + frameCount×4096` — an upper bound; v2 files land smaller): replace target slot file → idle slot files → playing animation last; eviction of idle slots is invisible to the server, which self-heals via play-ack timeout + re-upload. Slot files auto-resume after reconnect. Chunked per-frame messages exist because PubSubClient's buffer is uint16-capped (~64KB), so a whole animation can't fit in one message. On staging completion AND on playback start, the panel publishes the 9-byte `"ANIL"` + slot + echoed uploadId to `<base>/anim/loaded` (from `loop()`, not the MQTT callback); the server matches the echoed uploadId so stale acks are ignored.
- Slot file formats (`/a<slot>.bin`), sniffed by the first two bytes at playback start: **v1** (codec 0 upload) = frameCount (u16 LE) + delayMs (u16 LE) + frameCount × 4096 B raw frames, exact size `4 + count×4096`; **v2** (codec 1 upload) = magic `"A2"` (u16 LE 0x3241, bytes 0x41 0x32 — read as a v1 frameCount it's 12865 > 200, so the formats can't collide) + frameCount (u16 LE) + delayMs (u16 LE) + offset table (count × u32 LE, absolute file offsets of each frame blob, written as zeroes during staging and patched from a RAM array on completion) + blobs, each blob = frameFlags u8 + body, byte-identical to the wire ANIF bytes from offset 6. Playback start validates both formats (v1: exact size; v2: magic, count 2–200, delayMs ≥10 clamp, offset table monotonic non-decreasing with every blob inside the file so the last blob ends at/before EOF); a corrupt file of either format is deleted and its slotidx entry zeroed. During playback, v2 frames seek their offset and decode per tick — RAW bodies read straight into the 4 KB RGB565 draw buffer, PAL_RLE bodies expand palette runs into it (µs-scale at 240 MHz) — then `drawRGBBitmap` exactly as v1; read/decode failures get the v1 remedy (stop + delete + zero index entry). The upload RAM ring holds one blob per slot (4104 B slots: v2 blobs are 1–4097 B). Mixed fleet: firmware that predates v2 rejects v2 ANIFs on length (expects exactly 4102 B), never publishes `ANIL`, and the server's ANIL timeout re-sends the animation as v1 RAW — costs one redundant upload per animation per old panel, then the content-hash cache takes over.
- `.pio/`, `.vscode/.browse.c_cpp.db*`, and `.vscode/ipch/` are generated artifacts — never edit or commit them.
- ACMD v1 parametric command channel (`<base>/cmd`): see the "ACMD v1" section below — full spec (framing, opcode table, font/BLIT formats, parametric semantics).

## ACMD v1 — parametric command channel (`<base>/cmd`)

Server-rendered command batches executed by the firmware's Adafruit_GFX-equivalent RAM renderer (`handleAcmd`/`acmdTick` + the `acmdWriteLine`/`acmdDrawRect`/`acmdFillRect`/`acmdDrawCircle`/`acmdPixel` mirror in `src/main.cpp`). Pixel-exact mirror of the server's Java preview renderer — both transcribe `Adafruit_GFX.cpp`: writeLine Bresenham with steep swap + `err = dx/2`, fillRect as per-column vlines (so `w`/`h` = 0 still paints rows y−1,y), drawCircle with 4 initial + 8 symmetric writes, int16 arithmetic, out-of-bounds pixels silently dropped. Subscribe is QoS 0, not retained.

**Batch framing**: `"ACMD"` magic (u32 LE) + version u8 (=1; any other value silently drops the whole batch) + cmdCount u16 LE + commands. The whole batch renders into an offscreen work canvas, starting from black (a batch fully describes the frame — send CLS for a background), and commits (base-canvas swap + display push + parametric arming) only on full parse success; any truncation or out-of-bounds argument drops the batch and keeps the prior display. **Command framing**, per the v1 table: FIXED commands are opcode u8 + fixed args (no length field); PAYLOAD commands (only 0x07 BLIT, 0x10 FONT, 0x11 TEXT, 0x21 SCROLL) are opcode u8 + payloadLen u16 LE + fixedArgs + payloadBytes, where **payloadLen counts ONLY the trailing payload bytes** (never the fixed args). Any opcode not in the v1 table stops parsing and commits the parsed prefix (forward-compat rule: future opcodes must be payload-form, so an extended parser can skip an unimplemented one by advancing fixedArgsLen + 2 + payloadLen; a v1 parser cannot know an unknown opcode's fixedArgsLen, hence the stop).

**Opcode table** (coords u8, colors u16 LE RGB565, canvas 64×32):

| Op | Command | Layout |
|---|---|---|
| 0x00 | NOP | — |
| 0x01 | CLS | color u16 — fill canvas |
| 0x02 | PIX | x, y, color |
| 0x03 | LINE | x0,y0,x1,y1, color — GFX writeLine exactly |
| 0x04 | RECT | x,y,w,h, color — outline (GFX drawRect = 4 fast lines) |
| 0x05 | FILL | x,y,w,h, color — GFX fillRect semantics |
| 0x06 | CIRC | cx,cy,r, color — GFX drawCircle |
| 0x07 | BLIT [payload] | fixedArgs x,y,w,h u8×4; payload = 32 B palette (16 × u16 LE) + `(run u8, colorIdx u8)` pairs — same pair codec as phase-2 PAL_RLE but rows are w px (not 64): runs never cross rows, each row's runs sum exactly to w, run 1..w, colorIdx 0..15; decodes w×h and blits at (x,y), canvas-clipped. Violation → drop batch |
| 0x10 | FONT [payload] | no fixedArgs; payload = pageId u8 (0..3; else drop) + glyphCount u8 + glyphs `[code u8, w u8 (1..32), h u8 (1..32), xAdvance i8, xOff i8, yOff i8, bitmap h × ceil(w/8) bytes MSB-first]`. RAM storage only, 4 replaceable page slots, glyph data malloc'd per page (last duplicate code wins) |
| 0x11 | TEXT [payload] | fixedArgs fontId u8, x u8, y u8 (top of glyph line box), color u16 (5 B); payload = len u8 (1..255) + ASCII. Glyph at (penX + xOff, y + yOff), penX += xAdvance; unknown glyph → penX += 4; missing page → drop batch |
| 0x20 | SWEEP | cx,cy,r u8×3, color u16, speedDegPerSec u8 (1..255; 0 → drop). θ = (elapsedMs × speed / 1000) mod 360; endpoint (cx + r·cosθ, cy + r·sinθ) computed in double, `lround` (half away from zero); GFX line from center over the base canvas each tick. Identical-SWEEP commits carry the previous epoch — see Execution model |
| 0x21 | SCROLL [payload] | fixedArgs 9 B = x,y,w,h,fontId u8×5 + color u16 + speedMsPerPx u16 LE (≥1; 0 → drop); payload = len u8 (1..255) + ASCII (text scratch ≤ 256 B). Ping-pong marquee with pacing: penX oscillates between the head-visible extreme (penX = x, tail clipped right) and the tail-visible extreme (penX = x + w − textW, head clipped left) — the text never leaves the region; each extreme is HELD for `ACMD_SCROLL_HOLD_PX` (8) px-units before reversing, and one pass travels textW − w px in at least `ACMD_SCROLL_MIN_PASS_PX` (12) px-units (one px-unit = speedMsPerPx — a barely-overflowing text glides slowly instead of rattling); phase 0 = the head hold; a fitting text, textW ≤ w, renders statically at x; textWidth = Σ xAdvance (+4 per unknown glyph); each tick's full-base copy restores the region (base canvas is immutable after commit) and the text draws glyph-tops at y, clipped to the region |
| 0x22 | BLINK | x,y,w,h u8×4, periodMs u16 LE (≥1; 0 → drop). Alternate content (the base region, provided by each tick's full-base copy) ↔ black every periodMs/2, first half shows content |

**Execution model**: commit stops animation playback (KEEP slot files — same as a static frame) and supersedes the static-frame channel; a batch arms **all** its parametric primitives (SWEEP/SCROLL/BLINK), in command order, up to **4** (`ACMD_PARAMS_MAX`; further ones are validated but ignored). Parametric ticks run from `loop()` at a ~10 ms floor (target cadence 10–30 ms); each tick starts from a fresh copy of the immutable committed base canvas and applies the overlays in command order, so a later overlay draws over an earlier one where their regions overlap (the full-canvas copy IS the SCROLL/BLINK region-snapshot restore). All state derives from elapsed milliseconds since commit (never tick counts), so loop jitter cannot drift the phase. **Epoch carry-over**: a commit whose armed parametric SEQUENCE is identical to the live one (same count, order, types and parameters — SCROLL text bytes included) keeps the previous epoch — elapsed keeps accumulating from the earlier commit, so refresh republishes re-arm every overlay exactly where it is and QoS-0 arrival jitter cannot snap the sweep back to 0° or restart a marquee mid-bounce (radar's live refresh and its bouncing info-column lines rely on this); any change (a different sequence, fewer/more parametrics, none) or anything that clears the ACMD state (static frame, ANIM/ANIP play, reconnect auto-resume, reboot) arms all parametrics fresh at the new commit. A later static frame, ANIM/ANIP play, or reconnect auto-resume overrides ACMD normally (every path runs through `stopAnimation`, which clears the ACMD state). **Boot limitation**: nothing is persisted for command screens — after a reboot the panel falls back to the normal auto-resume behavior (retained base frame, else last slot animation) and font pages are gone until re-uploaded; the server re-sends ACMD when it re-pushes the screen.
